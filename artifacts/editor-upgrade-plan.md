## 1. Цель и границы

Последовательно получить редактор, в котором можно раскрыть нужные настройки, разместить устройство внутри понятного кадра, изменить его положение/поворот/масштаб, затем создать и экспортировать анимацию через нижний таймлайн.

Основная аудитория, подтверждённая пользователем: дизайнеры, которые регулярно делают концепты в Figma. Главный вход — скопированный PNG экрана: Alt+Tab в сервис → Ctrl+V → изображение сразу на выбранном устройстве. Настройка ракурса и создание анимации доступны по желанию. Подробный сценарий и три описанных пользователем движения камеры — раздел 10.

Прямо запрошено:

- Правая панель с независимо раскрываемыми разделами.
- Три инструмента: scale, rotate и transform; у rotate — кольца вокруг модели, как в примере.
- Большая центральная область с понятными границами вместо ощущения бесконечного холста.
- Нижняя панель анимаций с ключевыми точками и настройкой easing; возможность добавить motion blur.
- Слои слева и интерактивные ключи по третьему скриншоту второй подборки; отображение времени над стрелкой курсора при удержании/перетаскивании. Дублирующее время над слоями можно решить позднее.
- Простая настройка easing для выбранного участка между двумя ключами; готовые пресеты движения камеры как важная самостоятельная функция.
- Пресеты теней и пользовательский цвет через color picker или ввод цветового кода.
- Три первых движения камеры по словесному описанию пользователя: отъезд от наклонённого крупного плана к прямому центральному виду; переход из нижней перспективы к прямому виду; наезд из полного прямого вида к центру экрана под небольшим углом.
- Shift при перетаскивании курсора времени привязывает его к существующим ключам; выбор параметра камеры показывает настройки параметра, выбор камеры/участка анимации даёт доступ к easing. Детали взаимодействия уточняются на рабочей демке.
- Переключатель режимов изображения и анимации; названия подготовить с навыком `sasha`.
- Ctrl+Shift+E в режиме изображения копирует PNG текущего мокапа с прозрачным фоном в буфер, затем сообщает об успехе. Горячая клавиша не скачивает файл.
- Ctrl+Shift+E в режиме анимации открывает настройки экспорта. Экспорт видео с прозрачным фоном — обязательная функция.
- Поэтапная работа с отдельными решениями, без реализации всего списка за один раз.

Предложение для первой версии: сохранить одну модель в сцене; анимировать её положение, поворот и равномерный масштаб, а движение камеры вести отдельной дорожкой. Пресеты движения камеры прямо запрошены пользователем. Несколько устройств, библиотека шаблонов целых сцен, аудиомонтаж и новые эффекты не следуют автоматически из референсов и требуют отдельного запроса.

Готово, когда: Ctrl+Shift+E → сообщение об успешном копировании → Alt+Tab → Ctrl+V вставляет готовый мокап без фона; файл автоматически не скачивается, сцена не меняется.

### Итерация 3. Инструменты устройства

Цель: менять положение, ориентацию и размер модели непосредственно на сцене.

Для обсуждения используем названия «Перемещение», «Вращение», «Масштаб». Слово transform из запроса пока трактуется как перемещение; универсальный комбинированный манипулятор — отдельная возможная трактовка.

Три последовательные подытерации:

- [x] **T3.1 — Общая основа.** Описать независимые трансформации устройства, центр вращения и масштабирования, связь с числовыми полями. Учесть существующий `camera.roll`, внутреннее центрирование моделей и раскрытие шарниров. Определить преобразование старых проектов без визуального скачка.
- [x] **T3.2 — Перемещение и масштаб.** Добавить три режима в панель; ручки перемещения по осям и согласованным плоскостям; равномерный масштаб как предлагаемый начальный вариант. Числовой ввод и манипулятор меняют одни значения.
- [x] **T3.3 — Вращение.** Кольца X/Y/Z вокруг модели, подсветка выбранной оси, понятная активная область, корректное продолжение жеста при выходе курсора за кольцо. Решить необходимость свободного вращения внешним кольцом и привязки к угловому шагу.
- [x] **T3.4** Развести действия камеры, навигации и объекта: при работе с ручкой камера не начинает вращаться. Определить отмену текущего жеста через Esc и поведение при потере указателя.
- [x] **T3.5** Сгруппировать один законченный жест в один шаг undo; сохранять трансформации в проекте; исключить манипуляторы из PNG и видео.
- [x] **T3.6** Проверить обычный телефон, складной телефон, ноутбук и монитор; обе проекции камеры; смену модели и сброс.

Готово, когда: устройство перемещается, поворачивается кольцом и масштабируется; поля справа синхронны; undo отменяет целый жест; после открытия проекта вид совпадает; в экспорте ручек нет.

Перед реализацией: уточнить transform; выбрать локальные или мировые оси для первой версии, точку вращения и способ управления камерой. Перечисленные решения ещё не утверждают архитектуру.

Что полезно увидеть в новых примерах: не только общий вид, но и создание первого ключа, изменение существующего, настройку easing и путь к экспорту. Референсы этой итерации не задерживают обсуждение панелей и холста.

- [x] **A5.1** Описать данные: длительность, дорожка/свойство, время ключа, значение, способ перехода. Установить правила для первого/последнего ключа, одинакового времени и сокращения длительности.
- [x] **A5.2** Реализовать вычисление состояния сцены для заданного времени, включая явно выбранное поведение вращения. Отдельно решить короткий путь и возможность полного оборота, чтобы 0° → 360° не превратилось в неподвижность.

Готово, когда: пользователь ставит две разные позы, видит движение, возвращается к любому времени и получает ту же позу; сохраняет проект, открывает и продолжает редактирование.

Начальный переход — линейный; расширенное редактирование и экспорт завершаются следующими итерациями. Результат этого этапа — рабочая локальная версия для оценки UX.

### Итерация 6. Редактирование ключей, easing и пресеты камеры

- [x] **A6.2** Удалять, дублировать и перемещать ключи с понятным поведением при совпадении времени; сохранять undo/redo.

- [x] **A6.4** По выбору участка между двумя ключами показывать простые варианты easing с миниатюрами кривых по новому референсу 4. Предложение: основные варианты сразу, дополнительные — по раскрытию; точный набор согласовать на прототипе.

При выборе самой камеры дать доступ к параметрам движения/easing, сохраняя видимую область применения. Если переходов несколько, не применять правку ко всем без отдельного действия. Способ выбора участка проверить на демке.
- [x] **A6.6** Проверить редактирование на паузе, точность времени, горячие клавиши и восстановление выделения после отмены.
- [x] **A6.7** Реализовать три заданных пользователем сценария камеры из раздела 10: отъезд от крупного плана, выравнивание из нижней перспективы, наезд к центру экрана. Сделать предпросмотр и применение к текущей сцене с редактируемой длительностью. Общий характер движения задан; точные углы, расстояния, длительность и easing проверить на демке.

Готово, когда: можно выбрать участок из двух ключей, изменить easing и длительность; применить пресет движения камеры, донастроить результат и отменить применение. Видно, какой переход и какая дорожка изменяются.

Решения перед этапом: нужны ли несколько выделенных ключей и пользовательская Bézier-кривая сразу. Предложение — начать с одиночного выбора и готовых кривых, расширять по реальным сценариям.

Требуемые приложения и формат уточняются; MP4 и звук отдельно не запрошены. Последовательность PNG может быть материалом технической проверки, но не заменяет требуемый видеофайл.

## 6. Когда принимать решения

| До этапа | Решение | Рабочее предложение, не утверждение |
|---|---|---|

## 8. Режимы и экспорт: уточнение пользователя

### Названия и тексты по навыку sasha

Контекст: интерфейс редактора. Пользователь выбирает вид результата; источник на экране устройства при этом может быть картинкой или видео.

| Вариант | Названия | Оценка |
|---|---|---|
| Безопасный, рекомендуемый | Изображение / Анимация | Понятно называет два режима работы |
| Короткий | Кадр / Анимация | Компактнее, но «кадр» может восприниматься как часть видеоредактора |
| Более явный | Статичный мокап / Анимация | Однозначно, занимает больше места |

Рекомендация — «Изображение / Анимация» как два подписанных сегмента. Предлагаемое место — верхняя часть редактора рядом с основным действием; окончательное расположение проверить в компоновке.

| Элемент | Предлагаемый текст |
|---|---|
| Основная команда изображения | Скопировать PNG |
| Подсказка команды | PNG с прозрачным фоном · Ctrl+Shift+E |
| Короткое сообщение об успехе | Мокап скопирован |
| Текст системного уведомления | PNG с прозрачным фоном — в буфере обмена |
| Более явная альтернатива сообщения | PNG без фона скопирован в буфер обмена |
| Ошибка копирования | Не удалось скопировать PNG. Попробуйте снова |
| Действие после ошибки | Повторить |
| Явная команда сохранения изображения файлом | Скачать PNG |
| Основная команда анимации | Экспортировать |
| Окно | Экспорт анимации |
| Переключатель в окне | Прозрачный фон |

Точные сообщения о разрешениях показывать только при установленной причине ошибки. Успешный рендер PNG ещё не означает успешную запись в буфер.

### Контракт поведения

| Режим | Ctrl+Shift+E | Результат |
|---|---|---|
| Изображение | Рендер текущего мокапа без фона → запись PNG в буфер → уведомление после успеха | Можно вставить через Ctrl+V; скачивание не начинается |
| Анимация | Открыть настройки экспорта | Пользователь выбирает параметры, в том числе прозрачность, затем явно запускает экспорт |

Предложения для проверки UX: переключение сохраняет всю работу; в изображении воспроизведение останавливается на текущем моменте, таймлайн скрывается. Отдельно определить, как последующая статическая правка относится к сохранённым ключам. Открытие окна экспорта при проигрывании должно фиксировать понятное состояние превью. Фон для копирования/экспорта исключается временно и не удаляет пользовательское вложение из проекта.

### Проверенные ограничения и источники

- Запись PNG из canvas в системный буфер предусмотрена Clipboard API; доступ зависит от безопасного контекста и разрешения операции. Подтверждение записи приходит после завершения `write()`. Это подтверждение возможностей API, а не выполненный тест нашего приложения. [MDN: Clipboard.write](https://developer.mozilla.org/en-US/docs/Web/API/Clipboard/write).
- Уведомление ОС требует разрешения пользователя; без него браузер его не покажет. Исходное требование системного уведомления сохранено. Предложение — при недоступности использовать сообщение в редакторе, не связывая успех копирования с разрешением уведомлений. [MDN: Notifications API](https://developer.mozilla.org/en-US/docs/Web/API/Notifications_API/Using_the_Notifications_API).
- Для видео без фона альфа-канал сохраняют. Документация Chrome описывает прозрачное WebM, Apple — HEVC с альфа-каналом. Это разные пути, которые необходимо проверить в целевых приложениях; расширение файла само по себе не гарантирует нужный результат. [Chrome: прозрачность WebM](https://developer.chrome.com/blog/alpha-transparency-in-chrome-video), [Apple: HEVC Video with Alpha](https://developer.apple.com/videos/play/wwdc2019/506/).

УВЕРЕННОСТЬ: 95% в описанных свойствах API и необходимости сохранить альфа-канал. Совместимость будущего экспорта с целевыми приложениями пока не проверена; формат и механизм рендера не выбраны. Проверка готового файла входит в обязательные критерии, а не заменяется ссылкой на поддержку формата.

## 9. Камера: выбор параметров и проверка на демке

Прямое уточнение пользователя: при выборе конкретного параметра камеры должна открываться панель для его изменения. Easing относится к выбранной камере/анимации, а не подменяет Position X/Y/Z. Пользователь предпочитает уточнять детали на рабочей демке и по опыту пользователей сервиса.

| Выбор/действие | Ожидаемый результат | Статус |
|---|---|---|
| Position X, Y, Z или параметр вращения | Панель соответствующего параметра камеры; его значение и доступное управление | Требование пользователя; точный состав полей на демке |
| Ключ конкретного параметра | Время ключа и значение параметра | Предложение для демки |
| Камера как дорожка | Доступ к настройкам движения, пресетам и easing с явно показанным выбранным участком | Направление пользователя; способ выбора участка на демке |
| Участок камеры между двумя ключами | Длительность и easing именно этого перехода | Требование из предыдущего уточнения |
| Перемещение курсора времени | Превью текущего момента, время над стрелкой; выбранный контекст панели сохраняется | Первое поведение запрошено, сохранение контекста предложено |
| Перемещение курсора с Shift | Привязка к существующему ключу при приближении | Требование пользователя |

Для демки отдельно проверить: ключи только выбранной дорожки или всех видимых; расстояние срабатывания/отпускания привязки; поведение рядом с несколькими ключами; отображение активной цели. Удержание Shift не должно переносить сами ключи. При трёх и более ключах камеры область изменения easing всегда видна; выбор строки камеры не означает автоматическое изменение всех переходов.

Сценарий проверки: выбрать Position Z → изменить значение → выбрать Rotation Y → изменить значение → выбрать участок движения камеры → поменять easing → провести курсор с Shift через ключ → отпустить Shift → продолжить свободное перемещение. Пользователь должен понимать, что выбрано и что меняет панель на каждом шаге. Результаты демки записать как конкретные наблюдения и локальные правки, не считать текущую матрицу финальным макетом.

## 10. Основной сценарий и три пресета камеры

### Пользовательский сценарий

Источник — словесное описание пользователя от 20 октября. Аудитория: дизайнеры, регулярно создающие концепты. Задача: быстро показать экран своего интерфейса на устройстве и вернуть результат в рабочий процесс; при необходимости добавить движение.

1. Дизайнер копирует PNG экрана из Figma.
2. Переключается в сервис через Alt+Tab и нажимает Ctrl+V.
3. PNG сразу появляется на выбранном устройстве. Предложение: вставка не требует окна импорта или поиска файла и сохраняет выбранную модель.
4. При необходимости дизайнер меняет ракурс, свет, фон и тень.
5. Статичный результат: Ctrl+Shift+E копирует готовый прозрачный PNG; Alt+Tab и Ctrl+V возвращают его в Figma или другое приложение.
6. Анимация по желанию: переключение режима → готовое движение камеры либо ручные ключи → настройки → Ctrl+Shift+E открывает окно экспорта.

Приоритет UX: быстрый путь должен проходить без обязательного открытия всех настроек и без создания анимации. Вставка реального PNG и буфера слоя Figma — разные входные состояния; при втором нужен точный текст восстановления, учитывающий ОС. Это задача проверки существующего обработчика, а не замена входного сценария обязательной загрузкой файла.

### Пресеты: заданные состояния

Названия подготовлены по `sasha` и являются предложением; движение задано пользователем.

| Пресет | Начало | Движение | Конец |
|---|---|---|---|
| Отъезд от экрана | Крупный план центральной части экрана, вид под небольшим углом | Камера отдаляется и плавно выравнивает вид | Прямой вид, экран по центру кадра |
| Из нижнего ракурса | Камера смотрит на экран снизу, выраженная перспектива | Камера плавно переходит к фронтальному виду | Экран прямо перед зрителем, без исходного наклона |
| Наезд на экран | Прямой вид, экран полностью виден | Камера приближается к центральной части и постепенно меняет угол | Крупный план центра экрана под небольшим углом |

Две схемы названий для интерфейса:

- Рекомендуемая: «Отъезд от экрана», «Из нижнего ракурса», «Наезд на экран». Названия поясняют смысл даже до предпросмотра; короткие описания показывают конечный ракурс.
- Компактная: «Отъезд», «Выравнивание», «Наезд». Подходит для карточек с достаточно понятным предпросмотром.

Предлагаемые описания карточек: «От крупного плана к прямому виду», «От перспективы снизу к прямому виду», «От прямого вида к крупному плану».

Точные значения не выдумываем из описания: величину угла, дальность отъезда/наезда, степень обрезки и длительность подбираем в демке. Для первого пресета ещё не задано, должен ли в конце целиком помещаться корпус; для второго не задано изменение дистанции. Эти параметры можно оценить на предложенном визуальном результате. Первое и третье движения не обязаны быть точным обращением одной и той же траектории.

Рабочее предложение: пресеты двигают камеру относительно центра активного экрана выбранной модели, сохраняя настройки устройства. Проверить совместимость с ранее выбранным ракурсом, трансформациями устройства и проекцией камеры; изменение проекции при необходимости должно быть понятным и отменяемым. Зависимости и конкретная математическая модель здесь не выбираются.

### Приёмка на демке

- Вставленный из Figma PNG сразу отображается на выбранном устройстве; повторная вставка заменяет экран предсказуемо.
- Каждый из трёх пресетов узнаваем по описанным началу и концу; центр внимания остаётся на экране.
- Предпросмотр показывает движение до применения; длительность и easing доступны для настройки, применение отменяется.
- Статичный сценарий Figma → сервис → Figma работает независимо от анимационной ветки.
- Сбор дополнительных видеореференсов необязателен: полученного словесного описания достаточно для первого варианта движений и последующей визуальной оценки.

### Проверка

- `npm run typecheck`, `npm run build` и полный `npm test`: 23 сценария, из них 12 новых — модель анимации, тени, буфер обмена, манипулятор, анимация, движения камеры, экспорт кадров PNG, границы кадра.
